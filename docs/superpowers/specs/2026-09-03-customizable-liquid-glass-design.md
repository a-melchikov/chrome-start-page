# Настраиваемый Liquid Glass — дизайн

Дата: 2026-09-03  
Статус: согласован пользователем

## Цель

Добавить в раздел «Виджеты» компактные настройки Liquid Glass, чтобы
пользователь мог менять прозрачность, размытие и интенсивность тени, видеть
результат сразу и при необходимости одним действием возвращать стандартный
внешний вид.

## Область изменений

Настройки применяются к существующим поверхностям Markdown и Search. Они общие
для светлой и тёмной темы, а также для режима с обоями и без них. Цвета стекла,
рамки и тени продолжают автоматически адаптироваться к теме.

Панели управления, диалоги и остальные элементы интерфейса не получают Liquid
Glass. Новые разрешения Chrome, зависимости, динамические эффекты, отдельный
preview и разные профили параметров для тем или источников фона не добавляются.

## Пользовательский интерфейс

Закрытый по умолчанию раздел «Виджеты» содержит:

1. существующий переключатель «Эффект Liquid Glass»;
2. ползунок «Прозрачность» от 0 до 100% со значением по умолчанию 40%;
3. ползунок «Размытие» от 0 до 40 px со значением по умолчанию 18 px;
4. ползунок «Тень» от 0 до 100% со значением по умолчанию 50%;
5. кнопку «Вернуть значения по умолчанию».

Текущие числовые значения показываются рядом с каждым ползунком. Ноль процентов
прозрачности означает непрозрачный tint поверхности, 100% — полностью
прозрачный tint; размытие, рамка и тень регулируются независимо. Ноль процентов
тени убирает внешнюю тень, но сохраняет тонкую внутреннюю кромку стекла.

При выключенном Liquid Glass ползунки недоступны. Кнопка сброса остаётся
доступной, возвращает `40% / 18 px / 50%` и не меняет состояние переключателя.
Если значения уже стандартные, кнопка недоступна.

## Модель данных и миграции

Persisted schema повышается с v4 до v5. Поле
`appearance.liquidGlassEnabled` заменяется сгруппированной конфигурацией:

```ts
interface LiquidGlassConfig {
  enabled: boolean;
  transparency: number;
  blur: number;
  shadow: number;
}

interface AppearanceConfig {
  theme: Theme;
  backgroundColor: string;
  wallpaper: WallpaperConfig;
  liquidGlass: LiquidGlassConfig;
}
```

Стандартные значения:

```ts
const DEFAULT_LIQUID_GLASS = {
  enabled: true,
  transparency: 40,
  blur: 18,
  shadow: 50,
} as const;
```

Runtime validation принимает только конечные целые числа в диапазонах каждого
ползунка. Значения не округляются и не ограничиваются молча: некорректная
текущая конфигурация отклоняется существующей ошибкой структуры.

Миграции:

- v1, v2 и v3 получают `DEFAULT_LIQUID_GLASS` с включённым эффектом;
- v4 переносит `liquidGlassEnabled` в `liquidGlass.enabled` и добавляет три
  стандартных числовых значения;
- виджеты, layout, тема, цвет и обои сохраняются без изменений;
- будущие версии продолжают явно отклоняться.

## Live preview и сохранение

Существующая немедленная запись темы, цвета, обоев, переключателя и кнопки
сброса сохраняется. Для ползунков хук конфигурации предоставляет два отдельных
действия:

- preview обновляет React-состояние и синхронный config ref без записи;
- commit ставит актуальную конфигурацию в существующую упорядоченную очередь
  сохранения.

Движение ползунка вызывает preview, поэтому виджеты меняются сразу. Commit
происходит после `pointerup`, завершения клавиатурного изменения, `blur`,
закрытия диалога, `pagehide` и unmount. Повторные события для уже сохранённого
значения не создают лишнюю запись. Так быстрые движения не засоряют
`chrome.storage.local`, а последнее значение не теряется.

Ошибка commit показывается существующим глобальным сообщением об ошибке
хранилища. В памяти остаётся выбранное значение, как и при других немедленных
изменениях оформления; очередь сохраняет порядок относительно остальных
операций.

## Применение стилей

`App` сохраняет корневой класс `liquid-glass-enabled` на основании
`appearance.liquidGlass.enabled` и задаёт числовые значения через CSS custom
properties. CSS преобразует прозрачность в alpha tint, размытие — в пиксели, а
интенсивность тени — в theme-aware alpha внешней тени.

Светлая и тёмная темы используют общие пользовательские числа, но разные
цветовые формулы. Формулы калибруются так, чтобы стандартные значения визуально
совпадали с текущим доработанным стилем. Крайние значения диапазонов имеют
буквальный смысл: tint непрозрачен при 0% и прозрачен при 100%, blur отсутствует
при 0 px, внешняя тень отсутствует при 0%.

При выключении эффекта CSS-переменные могут оставаться на корне, но modifier
класс отсутствует: Markdown возвращается к непрозрачной базовой карточке, а
Search — к bare-виду без внешней капсулы. Fallback без `backdrop-filter`
сохраняет рассчитанный tint, рамку и тень.

## Компоненты и границы

- `storage/schema.ts` определяет schema v5 и `LiquidGlassConfig`.
- `storage/defaults.ts` экспортирует неизменяемые стандартные параметры.
- `storage/migrations.ts` валидирует v5 и мигрирует v1–v4.
- `useDashboardConfig` разделяет preview и commit, сохраняя единую очередь
  записи и lifecycle flush.
- `AppearanceDialog` показывает controls, числовые значения и reset.
- `App` выставляет modifier и CSS custom properties.
- `style.css` вычисляет theme-aware tint, blur и shadow без новых библиотек.

React-компоненты не обращаются к `chrome.storage` напрямую. Новое состояние не
дублируется в `localStorage` или отдельном storage key.

## Проверки

Автоматические тесты покрывают:

- стандартную конфигурацию v5;
- миграции v1–v3 со включёнными defaults и v4 с сохранением boolean;
- отклонение неправильных типов, дробных чисел и значений вне диапазона;
- закрытый раздел, подписи, диапазоны и отображаемые числа;
- disabled-состояние ползунков и независимость reset от переключателя;
- preview без промежуточной записи и commit для pointer, клавиатуры, blur,
  закрытия и lifecycle flush;
- CSS modifier и custom properties в `App`;
- сохранение стандартного внешнего вида и выключенного fallback;
- полный regression suite, production build и неизменный manifest.

Визуальная ручная проверка использует светлую и тёмную тему, однотонный фон и
пёстрые обои, а также крайние и стандартные значения каждого ползунка.

## Рассмотренные альтернативы

### Плоские поля в `AppearanceConfig`

Требуют меньше изменений в миграции, но разбрасывают связанные параметры рядом
с темой и обоями. Отклонено в пользу одной типизированной группы.

### Отдельный storage key

Позволяет не менять schema dashboard, но создаёт два источника истины и
усложняет упорядочивание записей и восстановление состояния. Отклонено.

### Расширенный набор параметров

Настройки насыщенности, яркости рамки и отдельные значения тем дают больше
контроля, но перегружают компактное меню. Отклонено в пользу трёх понятных
ползунков.

## Критерии готовности

- Все три параметра регулируются в согласованных диапазонах и отображают число.
- Изменения видны немедленно, но сохраняются только после завершения ввода.
- Последнее preview-значение не теряется при закрытии или завершении страницы.
- Настройки переживают перезапуск Chrome и корректно мигрируют с v1–v4.
- Reset возвращает `40% / 18 px / 50%`, не включая выключенный эффект.
- Стандартные значения соответствуют текущему визуальному балансу.
- Выключенный эффект и fallback без `backdrop-filter` сохраняют прежнее
  поведение.
- Разрешения и зависимости не меняются.
